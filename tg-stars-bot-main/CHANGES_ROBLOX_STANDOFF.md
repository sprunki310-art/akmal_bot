# Roblox + Standoff 2 Golda — что добавлено

Оба товара встроены в существующий проект **по образцу Brawl Stars и ручных
депозитов**: покупка списывает баланс и создаёт запись в уже существующей
таблице `game_orders`, админ обрабатывает заявку в Mini App («Админ → Игры»),
все уведомления уходят через `tg_notify.py` в чат с ботом.

Новый код НЕ трогает существующую логику Stars/Premium/Brawl — только
добавляет рядом.

## Файлы

| Файл | Что изменилось |
|---|---|
| `config.py` | `ROBLOX_PRODUCTS`, `STANDOFF_GOLD_PRODUCTS`, `STANDOFF_RULES_TEXT` |
| `db.py` | `get_active_game_orders()`, `get_user_game_orders()` — без изменений схемы |

| `webapp_static/index.html` | 2 новые карточки на главной, экраны покупки, вкладка «Заказы» показывает игровые заявки, админ-панель «Игры» умеет вести Standoff по этапам |

## Схема БД

Новых таблиц не потребовалось — `game_orders` уже была спроектирована
достаточно универсально:

```sql
CREATE TABLE game_orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER,
    username TEXT,
    category TEXT,        -- 'brawlstars' | 'roblox' | 'standoff'
    product_id TEXT,       -- напр. 'robux_400', 'gold_500'
    product_name TEXT,     -- напр. '400 Robux', '500 golda'
    price REAL,             -- сумма в сумах, списанная с баланса
    extra TEXT,             -- JSON: логин/пароль, email, скин, скриншот
    status TEXT DEFAULT 'new',
    admin_id INTEGER,       -- кто последний раз менял статус
    created_at TEXT,
    updated_at TEXT
)
```

`extra` — единственное «динамическое» поле:
- Roblox: `{"login": "...", "password": "..."}`
- Standoff: `{"skin_name": "...", "skin_price": 50000, "screenshot": "<base64>"}`

## FSM — Roblox (простая, 1 админ-решение)

```
[buy] --спишет баланс--> awaiting_credentials
      --пользователь вводит логин/пароль--> pending_admin
      --админ жмёт «Выполнено»--> done
      --админ жмёт «Отменить» (в любой момент)--> cancelled (возврат средств)
```

## FSM — Standoff Golda (многошаговая, через продажу скина)

```
[buy] --спишет баланс, админ уведомлён сразу--> pending_admin
      --админ вводит название скина + цену--> awaiting_screenshot
      --пользователь присылает скриншот--> screenshot_review
      --админ «Подтвердить»--> in_progress (пользователю уходят правила сделки)
      --админ «Отклонить»--> awaiting_screenshot (просьба переснять)
      --админ «Куплен»--> bought
      --админ «Передан поставщику»--> transferred
      --админ «Завершить»--> done
      На любом этапе (кроме done) админ может «Отменить» --> cancelled (возврат средств)
```

## Последовательность сообщений (Standoff, как было ТЗ)

1. Пользователь оплачивает → бот: *«✅ Ваша заявка отправлена на обработку.
   Ожидайте ответа оператора.»*
2. Админам (всем из `ADMIN_IDS`) уходит уведомление: ID заявки, `@username`,
   количество golda, сумма.
3. Админ открывает «Админ → Игры», вводит название скина и цену → бот
   пользователю: заявка принята + скин + цена + просьба прислать скриншот.
4. Пользователь прикрепляет скриншот (через вкладку «Заказы» → карточка
   заявки → «📸 Прикрепить скриншот»).
5. Админам приходит фото в чат + инструкция открыть Mini App для решения
   (кнопки ✅/❌ — в самом Mini App, а не в чате, как и остальная модерация
   в этом проекте — см. ручные депозиты).
6. Админ подтверждает → пользователю уходят обязательные правила сделки
   (не менять аватар/ник, не снимать/не менять цену скина, соблюдать до
   завершения).
7. Админ последовательно отмечает «Куплен» → «Передан поставщику» →
   «Завершено» — пользователь получает уведомление на каждом шаге.
8. По завершении в «Заказах» у пользователя появляется кнопка
   «⭐ Оставить отзыв» (переиспользует уже существующий механизм отзывов).

## Почему кнопки ✅/❌ не в чате, а в Mini App

В этом проекте админ-модерация уже полностью перенесена из кнопок в чате
в панель Mini App (см. `README.md`: «замена кнопок Принять/Отклонить в
чате»). Чтобы не плодить два разных UX для админа, Standoff/Roblox сделаны
так же: в чат приходит **уведомление** (текст или фото), а решение
принимается в разделе «Админ → Игры».

## Новые эндпоинты

```
POST /api/games/roblox/buy
POST /api/games/order/<id>/credentials
POST /api/games/standoff/buy
POST /api/admin/standoff/skin
POST /api/games/order/<id>/screenshot
POST /api/admin/standoff/screenshot/decide      {id, action: confirm|reject}
POST /api/admin/standoff/stage                  {id, stage: bought|transferred|done}
GET  /api/games/my-orders
```

Плюс расширены:
- `GET /api/admin/game-orders/pending` — теперь отдаёт не только
  `pending_admin`, но и все промежуточные статусы Standoff (для рендера
  нужной формы/кнопок в админке).
- `POST /api/admin/game-orders/cancel` — разрешён с любого активного этапа
  (не только `pending_admin`), чтобы можно было вернуть деньги в середине
  сделки Standoff.

## Известные допущения / что стоит проверить перед продакшеном

- Цена скина на площадке указана в **SC** (Standoff Coins — валюта
  торговой площадки в игре). Если у вас другое обозначение — замените в
  паре мест в `webapp.py` и `index.html` (ищите `SC`).
- Логин/пароль Roblox хранятся в `extra` (JSON) в открытом виде — так же,
  как email в Brawl Stars. Это соответствует остальной архитектуре
  проекта, но подразумевает, что доступ к серверу/БД ограничен.
- Линейная цена golda (140 сум/единица) зашита в `STANDOFF_GOLD_PRICE_PER_UNIT`
  в `config.py` — при изменении курса меняется в одном месте.
