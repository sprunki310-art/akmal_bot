# Akmal's Stars — бот + Mini App (после рефакторинга)

## Что изменилось

Раньше весь функционал (покупка звёзд/премиума, профиль, депозиты, рефералка,
отзывы, админ-команды) жил в `bot.py` как обработчики чата. Сейчас:

- **`bot.py`** — теперь занимается только одним: `/start` регистрирует
  пользователя, привязывает реферала и присылает одну кнопку «🛍️ Открыть
  магазин» (WebApp). Никакой другой логики покупок/депозитов/админки в боте
  больше нет.
- **Mini App** (`webapp_static/index.html` + `webapp.py`) — теперь содержит
  **весь** функционал:
  - покупка Stars и Premium (себе / другу);
  - профиль и баланс;
  - депозит тремя способами: карта (Freedom Pay), TON (автоматически по
    комментарию с вашим ID) и ручной перевод по реквизитам со скрином чека;
  - реферальная программа (ссылка, статистика, список рефералов);
  - отзывы после покупки (публикуются в канал `REVIEW_CHANNEL`);
  - смена языка (ru/uz);
  - **админ-панель** (видна только тем, чей ID указан в `ADMIN_ID`):
    сводка/статистика, поиск пользователей и начисление/списание баланса
    (замена `/addbalance`, `/checkbalance`, `/admin_remove`), модерация
    заявок на ручное пополнение (замена кнопок «Принять/Отклонить» в чате),
    экспорт базы в Excel.

Бот всё ещё шлёт уведомления в Telegram (бонус рефереру, пополнение,
одобрение/отклонение депозита и т.п.) — это просто push-уведомления, реальные
действия выполняются через API мини-аппа.

## Важная находка

При загрузке файлов их имена и содержимое оказались перепутаны (видимо, при
скачивании/архивации): `config.py` на самом деле содержал главный файл бота
на 2400+ строк, `db.py` — содержимое настоящего `config.py`, `Dockerfile` —
содержимое настоящего `db.py`, а `Admin_remove_money.py` — HTML-файл вашего
Mini App. Я всё восстановил по реальному содержимому, а не по именам файлов.
Также в исходном коде было заметное количество дублирующихся обработчиков
(например, три параллельные версии подтверждения депозита) — они объединены
в одну рабочую версию.

## Структура проекта

```
bot.py            — минимальный бот (/start + запуск фоновых потоков)
webapp.py         — Flask API: вся бизнес-логика + админ-эндпоинты + /api/sms/webhook
webapp_static/
  index.html      — Mini App (один файл: HTML+CSS+JS)
db.py             — работа с SQLite (manual_deposits, card_auto_deposits, reviews и т.д.)
config.py         — все константы и переменные окружения
tg_notify.py      — отправка уведомлений в Telegram через HTTP (без telebot)
telegram_sms_listener.py  — слушает CardXabarBot/HUMOcardbot, шлёт на /api/sms/webhook
requirements-listener.txt — зависимости для telegram_sms_listener.py (отдельно от бота)
fragment_api.py   — отправка Stars/Premium через Fragment (без изменений)
freedom.py        — Freedom Pay (без изменений)
ton_monitor.py    — мониторинг TON-кошелька (без изменений)
excel_export.py   — экспорт БД в Excel (добавлены новые таблицы)
Dockerfile, railway.json, requirements.txt, .env.example
```

**Удалены как неиспользуемые** (вся их функция теперь в `webapp.py`/`index.html`):
`keyboards.py`, `utils.py` (анимация «Отправляю звёзды…» теперь просто
спиннер в интерфейсе), `test_mode.py` (заглушки Fragment API — если нужны
для тестирования, импортируйте их функции прямо в `webapp.py` вместо
`fragment_api`).

## Переменные окружения (.env)

См. `.env.example`. Дополнительно теперь нужен:

```
WEBAPP_URL=https://ваш-домен.up.railway.app
```

Это публичный URL, по которому Telegram будет открывать Mini App (кнопка в
`/start`). Без него бот всё равно запустится, но кнопка открытия магазина не
появится.

Необязательные новые переменные (есть значения по умолчанию):
```
BOT_USERNAME=          # если не указан, бот сам спросит у Telegram через getMe
REVIEW_CHANNEL=@akmal_otzivi
MANUAL_CARD_NUMBER=5614683586724031
MANUAL_PHONE_NUMBER=90 023 50 01
```

## Как это работает технически

- Mini App общается с `webapp.py` через `fetch()`, передавая заголовок
  `X-Telegram-Init-Data` — это подписанные Telegram данные, backend проверяет
  HMAC-подпись на каждый запрос (как и раньше).
- Админ-эндпоинты (`/api/admin/...`) дополнительно проверяют, что
  `user_id` есть в списке `ADMIN_IDS` — иначе 403.
- Скрины чеков сжимаются на телефоне пользователя (canvas, до 1280px,
  JPEG) перед отправкой, чтобы не упираться в лимиты — хранятся как base64
  прямо в SQLite (таблица `manual_deposits`).
- Бот и Flask-сервер запускаются в одном процессе (`bot.py`), Flask — в
  отдельном потоке, как и раньше.

## Автоплатёж по картам (Uzcard / Humo) — новое

В мини-аппе появилась вкладка пополнения **«⚡ Автоплатёж»**: пользователь
выбирает карту (Uzcard, Humo — Visa пока без авто-подтверждения, см. ниже),
вводит сумму, получает номер карты и **уникальную точную сумму** к переводу
(с небольшой случайной доплатой, например 50 000 → 50 637 сум — так сервер
точно понимает, какая именно заявка оплачена). Дальше всё происходит само:

1. Пользователь переводит ровно эту сумму на карту.
2. Банк присылает уведомление об операции в Telegram через официальных
   ботов **@CardXabarBot** (Uzcard) или **@HUMOcardbot** (Humo) — в ваш
   личный Telegram-аккаунт (тот, что привязан к картам).
3. Скрипт `telegram_sms_listener.py` (входит в ваш Telegram как
   пользовательский аккаунт через Telethon, см. инструкцию ниже) видит
   это сообщение и пересылает его текст на `/api/sms/webhook`.
4. Сервер сверяет сумму с ожидающими заявками и **сам зачисляет баланс** —
   без вашего участия. Пользователь в мини-аппе видит это почти мгновенно
   (опрос статуса каждые 4 секунды) и получает уведомление от бота.

Если заявка не оплачена за `CARD_DEPOSIT_TTL_MINUTES` (по умолчанию 15
минут), она автоматически "сгорает" и сумму можно использовать повторно.

### Почему не Visa

У CardXabarBot/HUMOcardbot нет аналога для Visa — международные карты
уведомляют по обычной SMS от банка-эмитента, а не через Telegram-бота.
Поэтому Visa в `CARDS` (config.py) по умолчанию не настроена и просто не
появится в списке автоплатежа — переводы на неё (если когда-нибудь
понадобятся) останутся через вкладку «📸 Перевод» с проверкой администратором.
При желании это можно покрыть Android-приложением для пересылки SMS
(например, `github.com/bogkonstantin/android_income_sms_gateway_webhook`) —
оно умеет слать на тот же `/api/sms/webhook`, формат идентичен.

### Настройка телефона/аккаунта (один раз)

1. Убедитесь, что в вашем Telegram уже подключены @CardXabarBot и/или
   @HUMOcardbot и реально приходят уведомления об операциях.
2. Зайдите на https://my.telegram.org под тем же номером, откройте
   **API development tools** и создайте приложение (название и платформа —
   любые) — получите `api_id` и `api_hash`.
3. На сервере (или любой машине, которая будет постоянно онлайн):
   ```
   pip install -r requirements-listener.txt
   ```
4. Заполните переменные окружения для скрипта (отдельно от `.env` бота):
   ```
   TG_API_ID=...
   TG_API_HASH=...
   TG_PHONE=+998901234567
   WEBHOOK_URL=https://ваш-домен/api/sms/webhook
   WEBHOOK_SECRET=...        # тот же SMS_WEBHOOK_SECRET, что у бота
   ```
5. Запустите `python telegram_sms_listener.py`. В первый раз Telegram
   попросит код подтверждения (придёт в сам Telegram) и, если включена
   двухфакторная аутентификация — пароль. После этого появится файл
   `sms_listener.session`, и дальше вход будет автоматическим.
6. Держите скрипт запущенным постоянно (screen/tmux/systemd/pm2) — без
   него автоплатёж не подтверждается.

⚠️ `sms_listener.session` — это ключ от вашего личного Telegram-аккаунта,
храните его так же бережно, как пароль, и не публикуйте в открытом репозитории.

### Новые переменные окружения (.env бота)

```
CARD_UZCARD_NUMBER=8600...      # номер карты Uzcard
CARD_UZCARD_HOLDER=Имя Фамилия
CARD_HUMO_NUMBER=9860...        # номер карты Humo
CARD_HUMO_HOLDER=Имя Фамилия
CARD_VISA_NUMBER=               # оставить пустым, если авто не нужен
SMS_WEBHOOK_SECRET=long-random-string   # секрет для /api/sms/webhook
CARD_DEPOSIT_TTL_MINUTES=15     # сколько ждём оплату, опционально
```

### Резерв на случай сбоя

Если по какой-то причине автоплатёж не подтвердился (скрипт-слушатель
упал, бот изменил формат сообщения и т.п.), в админ-панели на вкладке
«Депозиты» появляется раздел **«⚡ Автоплатёж — ждут SMS»** с теми же
заявками — администратор может подтвердить или отменить их вручную, ровно
как и заявки на ручной перевод.



1. Указать `WEBAPP_URL` в Railway после первого деплоя (домен появляется
   только после деплоя — придётся передеплоить ещё раз после того, как
   узнаете адрес).
2. Telegram требует, чтобы Mini App открывался по HTTPS — Railway это даёт
   из коробки.
3. Проверить, что `ADMIN_ID` содержит верные numeric Telegram ID (не
   username), через запятую.
